# agent — 3단계: 실패 처리 (단기 기억 + 함수 호출 + 오류 대응)

Gemini API를 호출하는 CLI 에이전트. 프로세스가 살아있는 동안 대화 이력을 기억하고(단기 기억),
필요할 때는 모델이 스스로 도구를 골라 호출하며(함수 호출), 무엇이 실패해도 죽지 않고 이유를
말해준다(실패 처리).

## 도구 목록

| 도구 | 설명 | 예시 질문 |
| --- | --- | --- |
| `search_leetcode_problems` | LeetCode 비공식 GraphQL API를 실시간 호출해 주제(태그)별 문제를 검색 (제목·난이도·링크) | "그래프 알고리즘 리트코드 문제 추천해줘" |
| `recommend_programmers_problems` | 검증된 큐레이션 목록에서 주제별 프로그래머스 문제를 추천 (제목·레벨·링크) | "프로그래머스로 해시 문제 추천해줘" |

두 도구 모두 `tag`/`topic` 파라미터가 정해진 목록(enum) 중에서만 선택 가능하다. 사용자의 주제가
목록의 어떤 항목과도 명확히 일치하지 않으면(예: "시간복잡도", "문법") 모델은 도구를 억지로 호출하지
않고, 일치하는 게 없다고 말한 뒤 가장 가까운 대안을 제안하도록 설계했다.

## 실패 처리

`GeminiClient`가 Gemini 호출 실패를 성격별로 구분해서, 사용자에게는 원본 JSON 대신 짧은 한국어
안내만 보여준다.

| 상황 | 판단 기준 | 처리 |
| --- | --- | --- |
| 일시적 오류 | 503/502/504, 네트워크 예외(타임아웃 등) | 1회 자동 재시도 후에도 실패하면 안내 |
| 한도 초과 | 429 | 재시도 없이 바로 "오늘 다 썼다"고 안내 |
| 설정 문제 | 400/401/403/404 | 재시도 없이 "키/모델 이름을 확인하라"고 안내 |
| 모델이 답을 막음 | `finishReason != STOP`, `promptFeedback.blockReason`, 빈 응답 | 재시도 없이 "답을 만들 수 없었다"고 안내 |

도구 실행 실패는 기존처럼 `ToolResult.error(...)`로 값으로 돌아가 모델에게 전달되고, 모델이
사용자에게 자연스럽게 설명한다. 그리고 `Main`의 매 턴 처리는 `try/catch(RuntimeException)`으로
한 번 더 감싸져 있어서, 우리가 예상 못한 버그가 터져도 CLI 프로세스 자체는 죽지 않고 다음 입력을
계속 받는다.

## 준비

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 무료 Gemini API 키를 발급받는다.
2. `.env` 파일을 만든다.

   ```bash
   cp .env.example .env
   ```

3. `.env`의 `GEMINI_API_KEY` 값을 발급받은 키로 채운다.

## 실행

```bash
mvn compile exec:java
```

`나>` 프롬프트에 메시지를 입력하면 답변이 오고, 이어서 다시 물어보면 이전 대화 내용을
기억한 채로 답한다. 도구가 필요한 질문이면 `[도구 호출] ...` 로그가 먼저 찍히고, 그 결과를
반영한 답변이 이어진다. `exit` 또는 `quit`으로 종료한다.

## 수동 테스트 절차

### 1단계 (단기 기억)
1. "내 이름은 규림이야" 입력 → 아무 답이나 옴
2. "내 이름이 뭐라고 했지?" 입력 → "규림"이라고 정확히 답하면 단기 기억이 동작하는 것
3. `GEMINI_API_KEY`를 잠깐 지워보고 실행 → 죽지 않고 안내 메시지가 뜨는지 확인
4. `exit` 입력 → 정상 종료되는지 확인

### 2단계 (도구 호출)
1. "그래프 알고리즘 리트코드 문제 추천해줘" → `search_leetcode_problems`가 호출되고, 실제
   LeetCode 문제 목록(제목+링크)이 포함된 답변이 오는지 확인
2. "프로그래머스로 해시 문제 추천해줘" → `recommend_programmers_problems`가 호출되고,
   제목+레벨+링크가 포함된 답변이 오는지 확인
3. 일반 대화("내 이름은 규림이야")에는 도구를 부르지 않고 그냥 답하는지 확인
   (모델이 도구가 필요 없다고 스스로 판단하는지)
4. "리트코드에서 시간복잡도 문제 추천해줘"처럼 목록에 없는 주제를 물어봐서, 억지로 도구를
   부르지 않고 "그런 태그는 없다"고 솔직히 말하는지 확인

### 3단계 (실패 처리)
1. 아무 API 키나 임의의 문자열로 바꿔서 실행(예: `GEMINI_API_KEY=invalid mvn compile exec:java`)
   → 원본 JSON이 아니라 "요청에 문제가 있어요. API 키와 모델 이름이 올바른지 확인해주세요."처럼
   짧은 한국어 메시지만 뜨는지 확인
2. (선택, 재현 어려움) 요청이 몰릴 때 503이 뜨면, 1회 자동 재시도 후 그래도 안 되면 "서버가
   붐빈다"는 안내가 뜨는지 확인
3. 무료 티어 한도(하루 20회)를 다 쓴 상태에서 질문 → "오늘 사용 가능한 요청 횟수를 다 썼어요"
   안내가 뜨고 죽지 않는지 확인
4. 아무 오류나 겪은 뒤에도 CLI가 종료되지 않고 바로 다음 질문을 받는지, `exit`로 정상 종료되는지
   확인

## 테스트 기록

### 1단계

- **단기 기억 — 성공.** "내 이름은 ayla야" → "내 이름이 뭐라고 했지?"로 재질문했을 때 "Ayla"라고
  정확히 기억해서 답변했다. 다만 재질문 도중 `Gemini API 호출 중 네트워크 오류: request timed out`이
  몇 차례 반복됐다 — 당시 HTTP 타임아웃이 30초였는데, `gemini-3.6-flash`는 생각(thinking) 모델이라
  단순 응답도 10초 이상 걸리다 보니 타임아웃에 걸린 것. **변경**: 2단계에서 타임아웃을 30초 → 120초로
  늘려 해결했다.
- **API 키 삭제 시 정상 종료 — 성공.** 스택트레이스 없이 "GEMINI_API_KEY가 설정되어 있지
  않습니다..." 안내 메시지만 출력하고 `BUILD SUCCESS`로 정상 종료했다. 죽지 않고 이유를 알려준다는
  목표를 그대로 만족.

### 2단계

- **주제-태그 매칭 실패 사례 — 실패 발견 → 수정.** "리트코드에서 시간복잡도 문제 추천해줘"라고
  물었을 때, LeetCode에는 애초에 '시간복잡도'라는 태그가 없는데도 모델이 `graph`/
  `breadth-first-search`로 억지로 매핑해서 그래프 문제를 추천했다. 실패를 실패라고 말하지 않고
  그럴듯하게 얼버무린 사례. **변경**: 두 도구(`search_leetcode_problems`,
  `recommend_programmers_problems`)의 description에 "목록에 없는 주제면 도구를 호출하지 말고,
  없다고 솔직히 말한 뒤 가장 가까운 대안을 제안하라"는 지침을 추가했다. 같은 질문으로 재확인한
  결과, 도구를 호출하지 않고 "시간복잡도라는 태그는 없다"고 답한 뒤 `binary-search`,
  `dynamic-programming` 등 대안 태그를 제안하는 것으로 바뀌었다.
- **도구 선택 — 성공.** "그래프 리트코드 문제 추천해줘" → `search_leetcode_problems` 호출,
  "프로그래머스로 해시 문제 추천해줘" → `recommend_programmers_problems` 호출, 일반 대화에는
  도구를 부르지 않는 것까지 모두 의도대로 동작했다.

### 3단계

- **오류 메시지 정제 — 개선.** 2단계까지는 429/503 같은 오류가 나면 원본 JSON 에러 바디를
  그대로 사용자에게 출력했다(할당량 초과 테스트 때 실제로 지저분한 JSON이 그대로 찍힘).
  **변경**: `GeminiException`에 사용자용 메시지와 디버그 상세를 분리해서, 이제는 "오늘 사용
  가능한 요청 횟수를 다 썼어요. 내일 다시 시도하거나 다른 API 키를 사용해주세요."처럼 짧은
  한국어 메시지만 노출한다.
- **잘못된 키 — 성공.** `GEMINI_API_KEY`를 임의 문자열로 바꿔 실행 → 400 계열 오류를
  "요청에 문제가 있어요. API 키와 모델 이름이 올바른지 확인해주세요."로 정상 안내.
- **일시적 오류 자동 재시도 — 추가.** 이전에 503(서버 과부하)이 떴을 때 수동으로 다시 물어봐서야
  성공한 적이 있었다(2단계 테스트 기록 참고). **변경**: 503/502/504와 네트워크 예외는 1회
  자동으로 재시도하도록 했다.
- **최상위 안전망 — 추가.** `Main`의 턴 처리를 `try/catch(RuntimeException)`으로 감싸서,
  예상 못한 버그로 CLI 전체가 죽는 것을 방지했다(이전엔 이 방어선이 없었다).

## 알려진 제약

- **응답 지연**: `gemini-3.6-flash`는 생각(thinking) 모델이라 단순 호출도 10초 이상 걸릴 수 있다.
  HTTP 타임아웃은 120초로 넉넉하게 잡아뒀다.
- **무료 티어 한도**: 하루 20회 요청 제한이 있다(계정별). 반복 테스트하다 보면 금방 소진되니,
  429가 뜨면 한도 초과다 — 하루 지나거나 다른 키로 바꿔서 테스트한다. (재시도 대상이 아니라서
  바로 안내만 뜨고 끝난다.)
- **도구 주제 목록이 고정**: LeetCode 태그, 프로그래머스 topic 모두 미리 정해둔 목록 안에서만
  검색 가능하다. 목록에 없는 주제는 모델이 스스로 "없다"고 답하도록 유도했다.
- **재시도는 최대 1회, 로그 파일 없음**: 사용자 요청에 따라 재시도는 딱 1번만 하고, 실패 상세는
  화면에도 파일에도 남기지 않는다(간결한 메시지만 노출). 원인 분석이 필요하면 `GeminiException`의
  `getMessage()`(디버그 상세)를 코드에서 임시로 출력해보면 된다.
